# Snowflake role pattern

```
users -> functional roles -> access roles -> privileges on objects
```

```sql
-- access roles: one per database (or schema) and privilege level
CREATE ROLE IF NOT EXISTS AR_ANALYTICS_PROD_READ;
CREATE ROLE IF NOT EXISTS AR_ANALYTICS_PROD_WRITE;

GRANT USAGE ON DATABASE ANALYTICS_PROD TO ROLE AR_ANALYTICS_PROD_READ;
GRANT USAGE ON ALL SCHEMAS IN DATABASE ANALYTICS_PROD TO ROLE AR_ANALYTICS_PROD_READ;
GRANT SELECT ON ALL TABLES IN DATABASE ANALYTICS_PROD TO ROLE AR_ANALYTICS_PROD_READ;
GRANT SELECT ON FUTURE TABLES IN SCHEMA ANALYTICS_PROD.MARTS TO ROLE AR_ANALYTICS_PROD_READ;
GRANT SELECT ON FUTURE VIEWS IN SCHEMA ANALYTICS_PROD.MARTS TO ROLE AR_ANALYTICS_PROD_READ;

-- functional roles: what a person or service does
CREATE ROLE IF NOT EXISTS FR_ANALYST;
CREATE ROLE IF NOT EXISTS FR_TRANSFORMER;   -- dbt service
GRANT ROLE AR_ANALYTICS_PROD_READ TO ROLE FR_ANALYST;
GRANT ROLE AR_ANALYTICS_PROD_WRITE TO ROLE FR_TRANSFORMER;
GRANT USAGE ON WAREHOUSE WH_BI TO ROLE FR_ANALYST;
GRANT USAGE ON WAREHOUSE WH_TRANSFORM TO ROLE FR_TRANSFORMER;

-- roll functional roles up to SYSADMIN so admins can manage what they create
GRANT ROLE FR_ANALYST TO ROLE SYSADMIN;
GRANT ROLE FR_TRANSFORMER TO ROLE SYSADMIN;
```

Future grants at schema level take precedence over database level when both
exist; pick one level and stay consistent. Recheck grant semantics against
current Snowflake docs before applying in bulk.
